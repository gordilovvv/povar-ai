# Машинный блок состояния — утверждённая форма

Статус: выбран 2026-07-21 замером. Только дизайн, в коде не реализовано.
Шаги воронки — в `CHECKLIST.md`. Здесь только форма блока, который код генерит
каждый ход и подаёт модели после `system.md` и `checklist.md`.

Блок оптимизирован **исключительно под точность модели**. Человек его не читает.

---

## Форма

```
State: name: Игорь Гордилов | instagram: — | guestlist: LYLO | table: not raised | companions: 2 declared / 0 named
Done: greet; pitch parties once
Now: get first+last name (and every companion name if +1)
```

Три строки:

| Строка | Содержимое |
|---|---|
| `State` | факты из базы, через `\|`, прочерк если пусто |
| `Done` | пройденные шаги **словами**, через `;` — не номерами |
| `Now` | ровно один текущий шаг |

## Почему эта

Замер: `tests/probes/7-machine-state-format.ts`, десять форматов, четыре сценария
(не переспросить имя, не ждать необязательного ответа, ответить на вопрос не по
повестке, увидеть `+1`).

| Формат | Итог |
|---|---|
| **структура + именованные шаги** | **11/12, повторено дважды — 22/24** |
| YAML | 9/12 |
| императив с `BECAUSE` | 9/12 |
| флаги `key=value` | 11/12, затем 8/12 — нестабилен |
| S-выражения | 8/12 |
| JSON | 10/12 |
| проза | 10/12 |
| XML-теги | 7/12 |
| символьная нотация `⟦✓✓►···⟧` | 7/12 |

Выбор сделан по **воспроизводимости**, а не по разовому рекорду: только эта форма
дала одинаковый результат в двух независимых прогонах и шесть из шести на `+1`.

Отвергнуто замером: сжатые и экзотические нотации (символы, XML, S-выражения)
стабильно хуже. «Максимально машинный» вид ≠ максимально точный.

## Решающее открытие замера

Первые прогоны шли поверх старого `system.md`, где осталась прежняя секция `Flow`.
Результат был перевёрнут: проза побеждала 6/8, структурированные форматы 4/8, а
сценарий «инста необязательна» проваливали **все, 0/8**.

Причина не в форме. `system.md:67` прямо велит «No instagram yet → collect it first
(add_to_guestlist fails without it)». Блок состояния говорил «необязательно» —
модель слушала системный промпт.

После очистки `system.md` от секции `Flow` сценарий ожил (0/8 → 2/3), а преимущество
прозы исчезло: форматы сравнялись. Проза выигрывала не качеством, а тем, что она
одна пробивала противоречащий системный промпт.

**Правило, которое из этого следует:** блок состояния не перебивает `system.md`.
Правило клади туда, где оно побеждает — в системный промпт. Блок несёт только факты
и указатель.

## Что блок не делает

- не содержит политики и инструкций — они в `system.md`
- не содержит марок (`[✓] [→] [ ] […] [✗]`)
- не объявляет ничего нерушимым
- не выводит ничего поиском по тексту переписки

## Поля под спутников

`companions: 2 declared / 0 named` — из `party_guestlist.companions_total` и
`array_length(companions)`. Шаг 3 остаётся текущим, пока `named < declared`.

## Методологические долги замера

Признаны, не закрыты:

1. **Проба не логирует ответы модели** — счёт неаудируем пост-фактум.
2. **Чек сценария `+1`** (`/имя|зовут|name/i`) засчитает модель, которая переспросила
   имя самого гостя вместо имени спутника. Часть очков может быть мусором.
3. **n = 3 повтора на ячейку.** Разница 9 против 11 — шум. Надёжно только то, что
   повторилось дважды, и то, что стабильно на дне (XML, символы).
4. Специализация строки `Now` кодом («спроси имя спутника — заявлено 2, записано 0»)
   выглядит перспективно, но не замерена. Формат с `BECAUSE` дал лучший результат
   на одном сценарии и худший на другом — эффект неясен.
