# Тулы агента

Модель видит только `description`, схему входа и то, что тул вернул. Что не сказано там — не понято.

## Раскладка

- Один тул — один файл в `Intelligence/Tools/`, PascalCase.
- Общие типы тулов — `Lib/Tools.ts`. В папке тулов типов не заводим.
- Утилиты, общие для всех тулов, — `Intelligence/Tools/Utils.ts`. Локальное — в файле тула.
- Регистрация — `Intelligence/Tools/index.ts`.

## Форма файла

Сверху вниз: `name` → `description` → схема входа → константы → `handler` → экспорт.

```ts
const name = 'snake_case_имя';
const description = `...`;
const input = z.object({ ... });

const handler = async (ctx: ToolContext, raw: unknown) => { ... };

export default { name, description, input, handler } satisfies AgentTool;
```

`satisfies AgentTool` обязателен.

## Description

Это промпт, не документация. Одним абзацем, на языке остальных промптов, без markdown.

- Скажи, **когда звать**, а не только что тул делает.
- Список примеров закрывай обобщающим хвостом — без него модель читает список как исчерпывающий.
- Есть тул с пересекающейся зоной — скажи, когда НЕ звать, и назови его поимённо.
- Каждый параметр — фраза о том, что это и откуда брать значение.
- Перечисление — скажи, что делать, если ни один вариант не подошёл.

## Схема входа

- Вход от модели — непроверенные данные: только zod, `as` запрещён.
- Перечисления берём из общей схемы, а не переобъявляем в туле. Производные структуры типизируем от неё, чтобы новое значение давало красный tsc.
- Строки, уходящие пользователю или в базу, — `.trim().min(1)`.
- Обязательным делай только то, без чего действие невозможно: иначе модель придержит вызов, ожидая недостающее.

## Разбор входа

Одна точка — начало хендлера:

```ts
const parsed = input.safeParse(raw);
if (!parsed.success) {
    return badInput(parsed.error);
}
```

Ошибка входа возвращает поле и причину из zod. С непрозрачным кодом модель повторит тот же вызов.

## Результат

- Машинный статус плюс только те поля, которые модель использует на следующем шаге.
- Не пиши о том, чего не произошло: модель перескажет это пользователю.
- Модель обязана замолчать или не звать другие тулы — скажи это императивом, назвав запрещённый тул.
- Одинаковые по смыслу исходы возвращают одинаковый результат: «сделал» и «уже было сделано» с разным текстом модель прочитает как разные ситуации.

## Побочные эффекты

- Мутирующий тул идемпотентен: повтор не делает работу второй раз и не затирает первый результат. Гонки и захват — по общим идиомам проекта.
- Ноль затронутых строк различай: «уже сделано» и «объекта нет» — разное. Второе успехом не маскируем.
- Текст, уходящий пользователю дословно, — константа в коде; модель передаёт параметрами только переменные части.
- Побочный эффект, который делает другой тул, вызывай его хендлером, а не копируй логику.
- Сначала фиксируем факт в базе, потом внешний вызов.

## Логи

Одна строка на исход, тегом `[имя_тула]`, с идентификатором контекста. Ветку «уже было сделано» логируем отдельно от «сделал».
